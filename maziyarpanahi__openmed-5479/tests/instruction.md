# Issue

**Title:** Qualify packaged Tauri sidecars against the portable kit contracts

## Description

.

The Tauri host now checks the sidecar against a versioned artifact manifest (`js/openmedkit-tauri/src-tauri/sidecar_manifest.rs`, `openmed.tauri.sidecar` v1) before it starts the process or sends it any text. The manifest is sorted-key canonical JSON. It records the protocol version, the required commands, the target platform and architecture, and the size and SHA-256 of the sidecar and of every model file. The `openmed-sidecar-manifest` bin generates it. A missing, changed, added or incompatible artifact refuses with a value-free reason code and never downloads anything. `sidecar_command.rs` now starts the verified executable itself through `tokio::process`, with offline environment variables and bounded stdout and stderr reads. Each start gets a random generation id and a `ping` handshake. Request ids carry that generation, so a response from an earlier process or for another request is rejected. If the renderer abandons a request, the next call discards that process. `terminate()` (and `terminate_blocking()` from `RunEvent::Exit`) interrupts any running request and kills the child. Crashes, stderr terminal events, deadlines, and oversized or malformed responses come back as typed errors with a stable `reason`, which the TypeScript client now exposes. `tests/sidecar_qualification.rs` drives the real host against a synthetic `openmed-fake-sidecar` bin for every failure mode. It also runs all 52 vectors from `tests/fixtures/parity/offset_contract.json`; the fake engine replays the reference spans, so this proves the transport keeps offsets and Unicode intact, not model detection. `.github/workflows/tauri-sidecar.yml` runs that job on Linux, macOS and Windows by default. It also defines an opt-in `packaged-sidecar` lane that runs only on manual dispatch with `packaged_lane=true`. The lane builds the PyInstaller sidecar, provisions a local model, writes the manifest, and runs the ignored `tests/packaged_sidecar_lane.rs` against the shared golden vector. The manifest's file inventory uses the same field names as the portable bundle manifest in #5445 (`path`, `role`, `size_bytes`, `sha256`) and should converge with it.

Breaking: `OpenMedSidecarState::default()` and `with_model()` are removed, and the commands no longer spawn through `tauri-plugin-shell`. To migrate, generate a manifest, build the state with `OpenMedSidecarState::from_bundle(SidecarBundle::new(include_bytes!(...), SidecarBundle::bundled_sidecar_path()?, model_dir))`, copy `sidecar_manifest.rs` next to `sidecar_command.rs`, and call `terminate_blocking()` on exit (`examples/tauri/redact-app.md`). Dependencies: `sha2` 0.10 becomes a direct dependency (MIT/Apache-2.0; it was already in `Cargo.lock` through Tauri), `tokio` gains the `io-util`, `process` and `rt` features, and `tauri-plugin-shell` is dropped. `Cargo.lock` only loses crates.

Not covered: no CI run of the packaged lane yet, so there is no evidence from a PyInstaller-built sidecar on any OS. Locally the lane passed on macOS (x86_64 toolchain) with the real Python sidecar, started through a shell wrapper because PyInstaller is not in the offline cache, and a local copy of `OpenMed-PII-SuperClinical-Small-44M-v1`. It passed the golden vector, the model-backed leakage check and both negative controls, with 13 model files verified. The Linux and Windows fake-process jobs have not run, and no Tauri app bundle was built or code-signed. #4129 adds Linux-only Tauri checks in `tauri-client.yml` pinned to Rust 1.99.0; this workflow pins 1.87.0, the version validated locally. Whichever of the two merges second should fold them into one workflow.
