# Issue

**Title:** Register and package the React Native bridge for iOS and Android autolinking

## Description

.

This adds the native registration and packaging that React Native CLI autolinking needs for `js/openmedkit-react-native`. On iOS, `ios/OpenMedKitRN.m` registers the Swift class with `RCT_EXTERN_MODULE` and declares four `RCT_EXTERN_METHOD` promise methods whose selectors match the Swift `@objc` names. `openmedkit-react-native.podspec` targets iOS 17, uses `install_modules_dependencies`, and links the `OpenMedKit` Swift package product (up to the next major version from 3.2.0) through React Native's `spm_dependency`. On Android, a self-contained library `build.gradle` sets namespace `com.openmed.openmedkit.reactnative`. Its standalone defaults are AGP 8.7.3, Kotlin 2.0.21, JDK 17 and compileSdk 35, matching #3950, plus `react-android` 0.77.3 and OpenMedKit Android `v3.2.0` through a JitPack repository scoped to one group. The Kotlin sources move under `src/main/java`, and `OpenMedKitRnPackage` moves into its own file, which is where the CLI looks for it. `react-native.config.js` names the Android package import and instance.

`package.json` `files` now ships exactly the podspec, the export file, the Gradle module, the native sources, the config, the TypeScript sources and the README, and nothing from tests or fixtures. `"type": "module"` is removed because the CLI loads the CommonJS config with `require()`. On both platforms, native rejections keep their existing codes, but the message is now either the bridge's own fixed text or `OpenMedKit native call failed`. They no longer carry the underlying error object, input text, file paths or option values. The package README documents the minimum React Native version (0.77), the iOS and Android integration steps, and that no codegen spec is provided: the legacy module runs on the New Architecture through React Native's automatic interop layer.

Breaking: `peerDependencies.react-native` moves from `>=0.74` to `>=0.77`, and native rejection messages no longer include underlying error text or caller values. To migrate, upgrade the host app to React Native 0.77 or later and match on the rejection `code`, not the message. The package is private and could not be linked before this change, so no installed consumer is affected.

Not covered: No Gradle compile against the real `react-android` 0.77.3 and OpenMedKit Android `v3.2.0` artifacts was run. Neither artifact is in the local Gradle cache, so offline resolution fails. As partial checks, the build script was configured offline with Gradle 8.11.1, AGP 8.7.3 and KGP 2.0.21, and the Kotlin sources were type-checked with kotlinc 2.0.21 (`-Werror`) against hand-written React Native 0.77 and OpenMedKit API stubs that are not committed. No minimal iOS host app was built to link the pod and call the four methods from JavaScript; that needs CocoaPods resolution of React Native and the OpenMedKit Swift package, plus a device for MLX. As partial checks, the export file was compiled with `-Werror` against React Native's `RCTBridgeModule.h` macros (local 0.64 copy; the macro bodies match 0.77), and a harness confirmed that it registers `OpenMedKitRN` with the four promise selectors. The Swift module was type-checked for macOS against prebuilt OpenMedKit modules and a React stub. New Architecture interop is not exercised at runtime.
