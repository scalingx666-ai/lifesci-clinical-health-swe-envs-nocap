# Issue

**Title:** Add gRPC authentication, per-RPC authorization, and resource budgets

## Description

. Depends on #4436.

Every gRPC server now runs a new `GrpcSecurityInterceptor` (`openmed/service/grpc_policy.py`) ahead of any caller interceptors. It authenticates `x-api-key` or `authorization` metadata with the existing `auth.py` API-key and JWT verifiers. On mutual-TLS listeners it can instead use the peer certificate, through `mtls.verify_client_certificate_chain` and a newly shared `principal_for_mtls_identity`. Either way the caller becomes the same `AuthPrincipal` REST uses, and each RPC must hold the scopes of the REST route it mirrors, including route-scope overrides: `analyze:write`, `pii:read`, `pii:write`, `pii:write`. Rate and concurrency permits come from the REST throttle settings, through a new thread-safe `TokenBucketRateLimiter.try_consume` and `BlockingConcurrencyGate` in `throttle.py`. Each call's deadline is the smaller of the client deadline and the server budget. `GrpcLimits` sets grpcio's receive and send message limits, and checks text length, chunk count, per-chunk UTF-8 bytes, total stream text and a server-capped `max_buffer` before anything is joined, parsed or handed to a model. Refusals use canonical statuses (`UNAUTHENTICATED`, `PERMISSION_DENIED`, `INVALID_ARGUMENT`, `RESOURCE_EXHAUSTED`, `DEADLINE_EXCEEDED`) plus a value-free `openmed-reason` trailer. Permits are released exactly once, when the call's work settles. A cancelled stream is closed on the worker thread that ran it, so the warm pool's thread-local request bookkeeping stays balanced.

Breaking: gRPC now honours `OPENMED_SERVICE_AUTH_ENABLED`, `OPENMED_SERVICE_MTLS_PRINCIPALS` and the REST rate and concurrency settings. `serve()` refuses a non-loopback listener that has neither service auth nor mutual TLS (`grpc_auth_required`). To migrate, enable API keys or JWKS, or use an mTLS listener with principal mappings, and send credentials in call metadata. `StreamDeidentify` now caps `max_buffer` at 65,536 (it was unbounded), 4,096 chunks and 128 KiB per chunk, and an unset `chunk_size` splits text longer than 32,768 characters. The default receive limit is 16 MiB (grpcio's default was 4 MiB) and the send limit is 64 MiB (it was unlimited). To change any budget, pass `policy=GrpcServicePolicy(limits=GrpcLimits(...))` to `serve()`. Loopback calls with auth off stay anonymous, as before.

Not covered: A unary model call that is already running is not pre-empted. If it overruns the server budget, it finishes, its result is discarded with `DEADLINE_EXCEEDED`, and only then are its permits released. Streams stop at the next fragment boundary. Messages over the size limits are rejected by grpcio itself with `RESOURCE_EXHAUSTED` and no `openmed-reason` trailer, because the application never sees them. grpcio exposes only the client's leaf certificate, so certificate principals require a leaf issued directly by a CA in the client CA bundle.
