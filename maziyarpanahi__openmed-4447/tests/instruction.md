# Issue

**Title:** Run Swift span-equivalence tests from the shared Swift-Kotlin golden fixture

## Description

.

Swift now runs the repository-root Swift-Kotlin golden: the new `SpanEquivalenceParityTests` loads `fixtures/parity/` through `#filePath`, validates the schema and digests, and runs each case through the public `OpenMed.extractPII`, `extractPIIChunked`, and `deidentify(_:policy:)` path over an internal `OpenMedSpanRecognizer` seam. The test recognizer mirrors the Kotlin `LocalPiiRecognizer` patterns. `fixtures/parity/expected_spans.json` moves to schema version 2. It now has four cases (the original note, an emoji/ZWJ/flag/combining-mark case with emoji touching span boundaries, an overlap case under `clinical_minimal_redaction` that pins both `mask` and `keep`, and a Unicode case with no identifiers). Each case stores ordered spans with derived UTF-8 and UTF-16 offsets, policy actions, and the expected de-identified text. The new `span_parity_manifest.json` pins SHA-256 digests and lists every consumer with its CI gate, and `scripts/parity/update_native_span_fixture.py` (`--check`, `--write`) validates or refreshes the derived fields and digests. The Kotlin `SpanEquivalenceTest` was rewritten to the same contract under Robolectric. Both kits now check native index conversions, actions, and UTF-8 bytes, and carry negative controls for a shifted span, a changed label, a dropped span, changed fixture bytes, and a changed digest. `swift-test.yml` and `android-ci.yml` now trigger on `fixtures/parity/**` and `scripts/parity/**`, and they run the two gates. `docs/swift-kotlin-parity.md` documents the coordinate contract, consumers, update command, and review rules.

The gate caught one real Kotlin drift: the Android policy alias table did not map `medical_record_number`, so it canonicalized to `OTHER` (`[OTHER]`). Swift and Python canonicalize it to `ID_NUM` (`[ID_NUM]`). `PolicyProfiles.kt` gains that one alias. Without it, `policyDeidentificationMatchesSharedActionsAndBytes` fails.

Breaking: Android policy de-identification now canonicalizes `medical_record_number` to `ID_NUM`, so the token is `[ID_NUM]` instead of `[OTHER]` and profiles that keep `OTHER` now mask MRNs. If you match the old token, match `[ID_NUM]`. The Swift seam is internal (`@testable` only) and leaves every public backend default unchanged.

Not covered: Both kits run with `useSmartMerging = false`. Swift's semantic merge pass is Swift-only and the Kotlin flag is a no-op, so smart merging is outside this gate. Probing also showed that Swift's `Patient:` full-name semantic pattern matches across a newline and swallows the next field label (`Alex Rivera\nDOB` becomes `[PERSON]`). That needs its own fix. Also, `patient_name` canonicalizes to `OTHER` in Python, Swift, and Kotlin, so profiles that keep `OTHER` would keep it. It is left unchanged as broader policy-equivalence work. The watchOS/visionOS simulator jobs do not run the new suite, which is gated like the other `OpenMed` tests.
