# Issue

**Title:** Gate the fp16 WebGPU ONNX export on logit and span parity

## Description

.

`convert()` now gates `model.webgpu.onnx` before listing it. The new `openmed/onnx/webgpu_gate.py` runs the fp16 graph and its fp32 parent on ONNX Runtime CPU over deterministic synthetic token inputs at the optimized-graph validation lengths (one full and one padded row per length, capped at the model's maximum length) plus the sample note and any `--validation-text` corpus, and scores logit deltas with `evaluate_onnx_logit_parity`, token agreement, BIO span agreement and per-label recall loss on G1/G2 labels. ORT CPU runs fp16 nodes that have no CPU fp16 kernel in fp32, so CPU logits can match while the same graph overflows on a GPU; the gate therefore also reads every activation the artifact stores in fp16 from the fp32 graph and fails above 65504. `export_webgpu` keeps LayerNorm, Softmax, reductions, `Pow` and `Sqrt` in fp32 on top of ORT's default block list (op and node keep-lists are configurable), keeps chains of kept nodes in fp32, drops the duplicate `Cast` nodes and restores the topological order that the ORT converter breaks once ops are blocked, and stamps the keep-list into the model metadata. The value-free record (tolerances, evaluated and skipped lengths, aggregate and per-label deltas, probe summary, keep-list, SHA-256 of both graphs and of the synthetic inputs) goes under a new top-level `webgpu_fp16_gate` key in `openmed-onnx.json`, and `write_export_manifest`, `validate_onnx_bundle` and `hf_publish.publish_artifact` refuse a `webgpu` artifact without a passing record whose digest matches the file, so neither `--no-onnx-optimization` nor a direct `openmed.core.hf_publish` upload skips the gate.

Breaking: a failed gate now fails conversion with `WebGpuFp16GateError`; pass `--webgpu-gate-policy omit` (or `WebGpuFp16GateConfig(on_failure="omit")`) to drop the artifact and record the reason instead. `model.webgpu.onnx` keeps the listed ops in fp32 by default; pass `keep_fp32_ops=()` for the previous converter-only block list. Publishing a `webgpu` bundle exported before this change requires re-running the converter.

Not covered: the gate is a CPU proxy and does not execute WebGPU kernels (the browser lane is #3940). Random synthetic tokens rarely produce entity spans for a trained model, so span and recall evidence comes from the sample note and validation texts. CI's default lane installs neither `onnx` nor `onnxruntime`, so the 8 real-graph tests (overflow graph, well-scaled graph, tiny random BERT, near-tie precision graph, corpus handling, keep-chain export, two end-to-end `convert()` runs) skip there; they ran locally against onnx 1.23.2 and onnxruntime 1.31.1. As an offline sanity check of the defaults, a locally cached `dslim/bert-base-NER` export passed both unoptimized and optimized: max |Δlogit| 0.003, no token or span disagreement on 20 sample-note spans, peak fp16-stored activation 102.

Overlaps: contributor PR #4325 also changes `write_export_manifest` and `convert()` for provenance; this change keeps its evidence in the separate `webgpu_fp16_gate` key and keyword, so only textual conflicts are expected. `_consolidate_external_onnx_data` (#4884, #5430) is untouched.

Validation: `python -m pytest tests/ -q -m "not slow and not fuzz" --ignore=tests/unit/training/synthetic/test_dicom_overlays.py` (27521 passed, 240 skipped; the ignored module fails to collect in the shared venv because `pydicom` is not installed there), `python -m pytest tests/unit/onnx tests/unit/core/test_hf_publish_onnx.py -q` with onnx 1.23.2 and onnxruntime 1.31.1 available (237 passed, 23 skipped, including all 19 gate tests), the same files without onnx (11 pure gate tests pass, 8 real-graph tests skip), `python -m pytest tests/unit -k "docs or publication or mkdocs or export_matrix"` (154 passed), `ruff check .` and `ruff format --check .` (clean), `python scripts/security/check_effect_paths.py --check` (verified), `mypy` (clean), `python scripts/release/check_repo_policy.py --commits origin/master HEAD` (passed). The strict MkDocs build was left to CI.
