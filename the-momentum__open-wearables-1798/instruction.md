# Issue

**Title:** docs: compact coverage matrix with pinned headers

## Description

## What does this change?

The coverage page now renders its matrices as compact HTML tables instead of emoji markdown tables: provider names rotated in the header, dots instead of ✅/❌, the header row and metric column stay pinned while scrolling, and each data layer (Timeseries, Workout, Sleep, Women's Health, Meals, Health Scores) is a tab. Quick Overview uses the same style.

## Why?

With 14 providers the markdown tables became too wide to read - you had to scroll sideways and lost track of which column and which metric you were on. Pinned headers and narrow columns fit the whole matrix on one screen.

I ruled out a client-side React component: the tables stay as plain markup in the MDX and are still generated by `generate_coverage_docs.py`, so the pre-commit hook keeps them in sync with `ProviderCoverage` as before.

The HTML matrix would reach LLMs as empty cells (the `.md` page views that `llms.txt` links to, and `llms-full.txt`), so each matrix is also rendered as a plain markdown table with ✅/❌ inside `<Visibility for="agents">`, and the HTML version sits in `<Visibility for="humans">`. Quick Overview is hand-written, so its two copies have to be kept in sync by hand - there's a comment saying so.

## How did you test this?

- Compared the old and new pages: the same 632 supported cells in the detailed matrix, and an identical Quick Overview.
- `mint validate` passes. Clicked through every tab in `mint dev` in light mode, dark mode and at phone width.
- Re-running the generator leaves the file unchanged.
- Checked that the agent tables don't render on the web page, that the table of contents is unchanged, and that the hidden status text in each cell is the same as the dot. I could not check the `.md` output locally (`mint dev` doesn't serve it), so that needs a look after deploy.
