# Issue

**Title:** Add Apple Keychain adapters for portable policy and bundle trust secrets

## Description

.

OpenMedKit gains a small injectable `OpenMedSecretProvider` protocol (`get`, `metadata`, `put`, `rotate`, `delete`, `protectionReport`) addressed by opaque `OpenMedSecretReference` values that keep only a SHA-256 digest of the purpose and caller label (`SecretProvider.swift`). `OpenMedKeychainSecretProvider` (`KeychainSecretProvider.swift`) stores caller-supplied policy secrets and bundle trust material as data-protection Keychain generic passwords. Its configuration is explicit: a service, a required access group (`applicationDefault` or `named`), a `ThisDeviceOnly` accessibility class (default `whenUnlockedThisDeviceOnly`) and optional user-presence, passcode or biometry access control. Every call sends `kSecAttrSynchronizable = false` and `kSecUseDataProtectionKeychain = true`. Failures are fixed `secret_*` codes (missing, locked, invalidated, rotated, protection mismatch, unsupported, missing entitlement and others) that carry no bytes, labels, service or account strings, or OS messages, and there is no plaintext, cached or weaker-protection fallback. Rotation is a compare-and-swap on the version stored in `kSecAttrGeneric`. `protectionReport()` probes LocalAuthentication without a prompt, writes are refused when the device cannot provide the configured protection, and the report always says `secureHardwareClaimed: false`. Tests drive the provider through a fake `OpenMedKeychainItemClient` shim over `SecItemAdd`/`CopyMatching`/`Update`/`Delete`. The public behavior is documented in `docs/swift-openmedkit.md`.

Not covered: I could not run the real-Keychain round trip (`OPENMED_KEYCHAIN_INTEGRATION=1`). The unsigned macOS `swift test` runner and the unhosted iOS Simulator xctest bundle both get `errSecMissingEntitlement`, and the test records that as a typed `secret_missing_entitlement` skip. So the `kSecAttrGeneric` compare-and-swap match is verified only against the fake, and a signed host app is needed to exercise it. Locked-device behavior, biometry-enrollment invalidation and Secure Enclave semantics need a physical device.
