# Issue

**Title:** Bind async job, bulk-export and ingestion records to the submitting principal

## Description

.

Records created by `POST /jobs`, `POST /fhir/bulk/exports`, `POST /fhir/bulk/imports` and `POST /fhir/smart-backend/ingestions` are now bound to the authenticated principal that submitted them. A new reusable `openmed/service/keyed_digest.py` computes domain-separated HMAC-SHA256 digests under a deployment key (`OPENMED_SERVICE_DIGEST_KEY`, optional `OPENMED_SERVICE_DIGEST_KEY_ID`) and stores each one with `alg` and `key_id` markers. `openmed/service/job_ownership.py` digests the credential type, JWT issuer and subject (API-key ids are excluded, so key rotation keeps ownership) and decides access. `app.py` records the digest at submit and checks it before every status, manifest, report, summary and cancel route. Non-owners get the same `404` envelope as an unknown job id, checked before the `409` "not completed" answer so it cannot be used as an existence oracle. Literal `jobs:admin` / `bulk:admin` scopes override ownership; `*` and `namespace:*` do not. The digest lives on the `jobs.py` store record and on the in-memory `bulk_data.py` / `smart_backend.py` `_JobRecord`s. It is stripped from `job_response_payload`, is absent from status and webhook payloads, and is never logged. The local job store now writes `schema_version: 2`; version-1 records load as explicitly unowned, which makes them admin-only outside the `dev`/`test` profiles. With authentication disabled, nothing changes. `docs/serving/authentication.md` (new "Job Ownership" section) and `docs/serving/async-jobs.md` document the behaviour.

Breaking: with authentication enabled, a principal can no longer read or cancel another principal's job, bulk or SMART record (it gets `404`), and legacy or unowned `/jobs` records become `jobs:admin`-only outside `dev`/`test`. Outside `dev`/`test`, the service now refuses to start when API-key/JWT or mTLS auth is enabled without `OPENMED_SERVICE_DIGEST_KEY`. Migration: set `OPENMED_SERVICE_DIGEST_KEY` (at least 32 bytes, for example `openssl rand -hex 32`) and grant `jobs:admin` / `bulk:admin` to operators that must see every job.

Not covered: master has no download route for bulk outputs and no cancel route for `/jobs`, so the binding covers the routes that exist (status, manifest, report, summary, cancel). There is no shared `_FILE` secret resolver on master, so the key is read from plain env only. Key rotation has no previous-key list: records digested under an old key fail closed to admin-only until their TTL expires. In `dev`/`test` without a configured key, the ephemeral per-process key has the same effect on persisted `/jobs` records after a restart. Bulk and SMART records are in-memory only, so the store migration applies to `/jobs`. PR #4437 adds a separate `auth.principal_digest()` for Journey audit records; the two should be unified onto `keyed_digest.py` when both land. #3918 is expected to reuse `keyed_digest.py` and its key configuration.

Validation: `pytest tests/unit/service/test_job_ownership.py` (15 passed, 11 subtests: owner, rotated-API-key owner, admin, other and wildcard principals on every `/jobs`, bulk export/import and SMART read and cancel route; 404 bodies identical to an unknown id; non-owner cancel leaves the job running; legacy v1 store records in prod vs test; auth-disabled records unowned and visible; digest absent from responses, webhook payloads, logs and the store's principal names), `pytest tests/unit/service` (all passed), `pytest tests/ -m "not slow and not fuzz" --ignore=tests/unit/training/synthetic/test_dicom_overlays.py` (27001 passed, 226 skipped, 11367 subtests passed; the ignored file fails to collect in the shared venv because `pydicom` is not installed, same as on master), `pytest tests/unit -k "docs or publication or mkdocs"` (152 passed; the strict MkDocs build was left to CI), `ruff check .` and `ruff format --check .` (clean), `scripts/security/check_effect_paths.py --check` (verified), `mypy` (clean), `scripts/release/check_repo_policy.py --commits origin/master HEAD` (passed).
