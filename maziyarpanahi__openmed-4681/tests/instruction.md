# Issue

**Title:** Enforce the iOS Simulator MLX boundary and run OpenMedKit tests on the Simulator

## Description

.

mlx-swift aborts the process on the iOS Simulator (a libc++ hardening assertion on a null bundle `resourceURL` while it looks up its Metal library). Before this change, `OpenMedMaple(modelDirectoryURL:)` and both `OpenMedVisionLanguageModel.load` variants reached MLX there, and running the OpenMedKit tests on an iPhone simulator crashed 8 MLX tests. This PR moves the existing Simulator/Apple-silicon check into one small shared gate, `OpenMedMLXRuntimeSupport` in `OpenMedMLXPipeline.swift`. `MLXTokenClassificationPipeline.isRuntimeSupported` now forwards to it, so the zero-shot and Privacy Filter guards are unchanged. Maple init, both Compass loads and the `OpenMed(backend: .mlx)` path now check the gate before any file read, Hub download or MLX call, and throw `OpenMedMLXRuntimeError.unsupportedPlatform`, which is now public, `Equatable` and `Sendable` and carries no values. `OpenMed.clearRuntimeMemoryCache()` does nothing where MLX cannot run, because the share extension calls it after CoreML work and it would otherwise reach the MLX allocator on the Simulator.

A task-local `simulatesSimulator` seam (internal; it can only take MLX support away, never grant it) lets `MLXSimulatorBoundaryTests` prove the refusal on macOS for every entry point. Each check has a negative control: on a supported host the same call without the seam must fail for a different reason, such as Maple's `missingFiles`. On the Simulator lane, the same tests run the real guard. The Hub test registers a `URLProtocol` that refuses all requests and asserts that no request started and no progress was reported. MLX-dependent tests skip through the same gate (`skipUnlessMLXCanRun()` in both `requireUsableMLXRuntime()` helpers and in the Compass local-artifact test).

`.github/workflows/swift-test.yml` adds a `test-ios-simulator` job. It runs `xcodebuild test` for `OpenMedKitTests` and `ExtensionTests` on an available iPhone simulator and lists the skipped tests with their reasons in the step summary. It fails if the MLX skips go missing or if the test runner restarts after a crash. The job is appended at the end of the file to stay clear of #4445's `build-ios` edits. `docs/runtimes/apple-platforms.md` documents the boundary, the error and the local command.

Note for #4449: no new error case is added. The PR reuses `OpenMedMLXRuntimeError.unsupportedPlatform`, which #4449's `ValueFreeErrorSentinelTests` catalogue already samples, so no new sample is needed there. The only change to that type is that it is now `public`, `Equatable` and `Sendable`. A trial merge of #4449 into this branch merges cleanly. Its catalogue test then reports no gap for `OpenMedMLXRuntimeError`; the only gaps it reports are `WFDBError` and `VoiceEmbeddingError`, which landed on master after #4449 was opened, so #4449 needs a rebase on master either way. The edits to `OpenMedMapleMLX.swift` and `OpenMedCompassRuntime.swift` are a doc comment plus one guard line per entry point, away from the hunks #4445 and #4449 change.

Not covered: physical-device MLX runs (device qualification stays with #3716). The CI job could not be run on GitHub-hosted runners from here; it was run locally with the same `xcodebuild` command, and its report script was checked against both logs.
