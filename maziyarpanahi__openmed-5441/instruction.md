# Issue

**Title:** Add Android Keystore adapters for portable policy and bundle trust secrets

## Description

.

This adds `com.openmed.openmedkit.secrets` to OpenMedKit Android: an injectable `OpenMedSecretProvider` contract (get, put, rotate, delete and describe by an opaque purpose-plus-label reference) and `AndroidKeystoreSecretProvider`, which keeps HMAC-SHA256 and AES-256-GCM keys non-exportable in the Android Keystore under per-purpose aliases (`openmed.<purpose>.<label>.v<n>`) and reads version state back from the alias list, so nothing is written to preferences, files or caches. Keys are created with an explicit `KeyGenParameterSpec` or `KeyProtection` (purposes, digest or GCM mode, user authentication with a validity window, StrongBox, unlocked-device), and the provider then reads `KeyInfo`, reports the observed security level (StrongBox, TEE, hardware with an unreported tier, or software), origin and authentication properties, and deletes the new key instead of returning it when that protection is below the requested `OpenMedSecretPolicy`. StrongBox `PREFERRED` falls back to the TEE and reports the fallback, while `REQUIRED` refuses (and needs API 31+, where the tier is verifiable); `KeyPermanentlyInvalidatedException`, `UserNotAuthenticatedException`, `StrongBoxUnavailableException` and API 33 `KeyStoreException` codes, including wrapped causes, become value-free codes such as `secret_invalidated` and `secret_locked`, with no message or cause carried over. `deid/DeidentifyEngine` now keys its `HASH` replacements and span digests through a provider; Keystore access sits behind a narrow `OpenMedKeystore` seam, so the Robolectric tests use an in-memory fake that throws the real platform exceptions, and `docs/android-keystore-secrets.md` covers references, required versus reported protection, failure codes, migration and the `fullBackupContent`/`dataExtractionRules` exclusions host apps should add. The policy-profile `com.openmed.openmedkit.DeidentifyEngine` behind the `OpenMedKit` facade is unchanged.

The new classes add about 67 KB to the release AAR with no new dependencies, so `android/gradle/budgets.properties` raises `aar.maxBytes` from 512 KiB to 576 KiB (measured 563,634 bytes). #5433 raises the same line to 608 KiB; keep the larger value if both land.

Breaking: `DeidentifyEngine()` no longer hashes with the built-in public salt; it leaves `textHash` empty and refuses `HASH` with `OpenMedSecretException` (`secret_missing`). `DeidentifyEngine(hashSalt)` is deprecated, and under the default `HashKeyPolicy.STRICT` it refuses `LEGACY_PUBLIC_HASH_SALT`, as does a provider-backed engine whose stored key equals it (`secret_public_default`). Migration: call `rotate(OpenMedSecretReference.DEIDENTIFY_HASH)` (or `put` a shared secret) and build `DeidentifyEngine(AndroidKeystoreSecretProvider())`; to reproduce pre-4.0 digests during a migration, pass `HashKeyPolicy.ALLOW_LEGACY_PUBLIC_SALT` explicitly.

Not covered: StrongBox and TEE security-level reports, lock-screen and biometric-enrollment invalidation, and real `AndroidKeyStore` exception behavior need a physical device; here they are exercised only through the fake and the spec-builder tests. Master has no `androidTest` source set, so the optional device lane is documented rather than added. Per-operation (`CryptoObject`) biometric authentication is out of scope; a policy requires `validitySeconds >= 1`.

Validation: `cd android && ANDROID_HOME=$HOME/Library/Android/sdk ./gradlew :openmedkit:verifyAndroidBudgets --offline` with JDK 11 (139 unit tests passed, release AAR 563,634 bytes within the 589,824-byte budget; this runs `testDebugUnitTest`), `.venv/bin/python -m pytest tests/unit -k "docs or publication or mkdocs or android" -q` (203 passed, 17 skipped), `ruff check .` and `ruff format --check .` (clean), `python scripts/security/check_effect_paths.py --check` (effect_paths_verified), `mypy` (no issues), `.venv/bin/python -m pytest tests/ -q -m "not slow and not fuzz" --ignore=tests/unit/training/synthetic/test_dicom_overlays.py` (27506 passed, 232 skipped). The full-suite run ignored `tests/unit/training/synthetic/test_dicom_overlays.py`, which fails to collect in the shared venv because `pydicom` is not installed. The strict MkDocs build was left to CI because `mkdocs` is not installed locally.
